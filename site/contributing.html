Community & Development

Contributing Guide

Thank you for considering contributing to Renderd! Please review our engineering standards and rules before submitting pull requests.

REPO-0001 §1.2

Engineering Non-Negotiables

🛡️

No Unsafe Code in Library Crates

unsafe is strictly prohibited outside designated FFI boundary crates (renderd-vt-sys and renderd-sc-sys). Every unsafe block in FFI crates requires a detailed safety justification comment.

🚫

No unwrap() or expect()

Never use unwrap() or expect() in library crates. Use the ? operator and explicit error types. expect() is permitted in tests with descriptive error messages.

📐

DAG Dependency Graph

Dependencies flow strictly downstream. A crate at layer N may never import from layer N+1 or higher. Monolithic or bi-directional crate dependencies are rejected by the compiler.

⚡

Sacred Latency Path

Any pull request modifying the capture → encode → send or receive → decode → present pipeline must include benchmark validation. Regression over 5% in p99 latency is blocked.

Development Cycle

Local Verification Workflow

Run these verification checks locally before opening a pull request. CI runs these exact checks across macOS and Windows runners. 

# 1. Format check
cargo fmt --check

# 2. Workspace Clippy (zero warnings policy)
cargo clippy --workspace --all-targets -- -D warnings

# 3. Test execution
cargo nextest run --workspace

# 4. Dependency & license audit
cargo deny check

# 5. Spell check
typos
REPO-0001 §20

Conventional Commits

All commits must follow the Conventional Commits specification.

PrefixScope ExampleDescription
feat(...)feat(proto)New feature or schema field
fix(...)fix(frame)Bug fix or reassembly patch
docs(...)docs(site)Documentation changes
ci(...)ci(workflows)CI/CD pipeline updates
refactor(...)refactor(net)Code refactoring with no behavior change
perf(...)perf(abr)Latency or throughput optimization
test(...)test(clock)Adding or updating unit/property tests
💡
Example commit message: feat(frame): add sliding-window fragment reassembly buffer state machine (#026)
Pull Requests

PR Submission Checklist

  • ✅ Code passes cargo fmt --check
  • ✅ Zero warnings on cargo clippy --workspace --all-targets -- -D warnings
  • ✅ All unit, integration, and property tests pass (cargo nextest run)
  • ✅ No security advisories or unapproved licenses (cargo deny check)
  • ✅ Target crate is reviewed against .github/CODEOWNERS
  • ✅ Commit messages adhere to Conventional Commits
