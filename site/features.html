Key Features

Every feature in Renderd is built around a single constraint: display-class latency with zero cloud dependency.

Performance

Zero-Copy Capture & Present

On macOS, ScreenCaptureKit delivers display frames as GPU-resident IOSurface objects. These are handed directly to VideoToolbox's VTCompressionSession without any CPU copy — the pixel data never leaves the GPU bus on the encode side.

On Windows, decoded video frames (NV12/P010) remain on the GPU and are passed directly to the D3D12 render pipeline, then presented via a DXGI swap chain. No readback to system RAM at any point.

Codec Pipeline

Hardware-Accelerated Video

H.265 primary, H.264 fallback. Hardware encode and decode on both sides. Software encode/decode is never used — it is CPU-prohibitive at 60 FPS.

Codec HW Encoder (macOS AS) HW Decoder (Windows) Encode Latency Notes
H.265 (HEVC) ✅ VideoToolbox ✅ D3D12VA / NVDEC / QSV Low (~7–11ms @ 1080p) Primary 10-bit HDR capable
H.264 (AVC) ✅ VideoToolbox ✅ D3D12VA / NVDEC / QSV / DXVA2 Low Fallback 8-bit only
AV1 ✅ VideoToolbox (M3+) ⚠️ RTX 30+, Intel Arc only Higher Future v2.0
VP9 ❌ No HW encoder — — Eliminated
💡
H.265 provides approximately 40% better compression efficiency than H.264 at equal perceptual quality, directly reducing frame size, datagram count, and network transmission time. Codec selection is negotiated during the SessionHello / SessionConfig exchange.
Synchronization

Vsync Phase Synchronization

The single most important differentiator between a display extension tool and a screen casting demo.

⚠️

The Dual-Vsync Problem

Without synchronization, frames randomly straddle vsync boundaries. Latency oscillates by up to one full frame period (16.7 ms at 60 Hz). Average glass-to-glass latency is pipeline latency plus half a frame period — not pipeline latency alone.

✅

Renderd's Solution

The viewer sends VsyncReport messages every ~16.7 ms over QUIC Stream 0. The host computes clock offset, predicts the next viewer vsync, and schedules capture to arrive at the viewer 2–5 ms before its vsync deadline. Result: stable, single-vsync, low-jitter presentation.

Phase Sync Protocol (QUIC Stream 0)
Viewer → Host (every ~16.7 ms)
VsyncReport { vsync_period_ns, vsync_phase_ns, clock_epoch_ns }

Host computes
clock_offset = (recv_time - clock_epoch_ns) - rtt/2
capture_time = next_viewer_vsync - encode_latency - rtt/2

Result: frame arrives at viewer 2–5 ms before vsync → consistent single-vsync present
Security

Secure by Design

🔑

SPAKE2+ Pairing (RFC 9382)

One-time pairing via 6-digit PIN. Resistant to offline dictionary attacks. Mutual authentication — neither side can complete without knowing the PIN. Perfect forward secrecy.

🔒

TLS 1.3 via QUIC

All traffic encrypted via TLS 1.3 mandatory in QUIC. Subsequent sessions use mutual TLS certificate verification — no PIN re-entry. Certificates are self-signed, derived from the PairToken via HKDF-SHA256.

🗄️

System Keychain Storage

PairToken stored in macOS Keychain Services (kSecClassGenericPassword) and Windows Credential Manager (CredWrite). Never written to disk in plaintext.

Congestion Control

Adaptive Bitrate Control

Renderd's ABR engine operates on two timescales to handle both sudden congestion events and long-term bandwidth trends:

  • Reactive (100ms): Drops bitrate immediately on fragment loss signals
  • Proactive (500ms): Gradually increases bitrate when network is clear

The asymmetric ramp rate ensures rapid recovery from congestion while avoiding the slow 6-second recovery that a symmetric ±5% scheme would produce.

Networking

Zero-Configuration Discovery

📡

mDNS / Bonjour

Automatic LAN peer discovery using mDNS (RFC 6762) and DNS-SD (RFC 6763). Service type: _renderd._udp.local.

On macOS, uses dns_sd.h (system Bonjour) — not pure-Rust mDNS crates which conflict with mDNSResponder's exclusive ownership of port 5353.

🔧

Manual IP Fallback

Enterprise networks frequently block multicast. The viewer UI provides a "Connect manually…" option accepting a host IP address and port, enabling deployment in environments with IGMP snooping, managed switches, or VPN tunnels.

Developer Experience

Layered Configuration

Powered by Figment, Renderd supports a layered configuration system where each source overrides the previous:

  1. Built-in defaults
  2. TOML configuration file (renderd.toml or renderd-viewer.toml)
  3. RENDERD_* environment variables
  4. CLI flags (highest priority)

Configuration schemas include RenderdConfig, HostConfig, ViewerConfig, NetworkConfig, CryptoConfig, and AbrConfig.

# renderd-host.default.toml
# Canonical macOS host daemon configuration

[host]
fps = 60
codec = "h265"
display_index = 0

[network]
port = 9901
max_datagrams_in_flight = 64

[abr]
min_bitrate_kbps = 2000
default_bitrate_kbps = 20000
max_bitrate_kbps = 50000

[crypto]
pair_token_keychain_service = "renderd-pair"
