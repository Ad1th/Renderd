The Problem

Why Renderd Exists

Software display extensions between macOS and Windows have historically suffered from fundamental latency, image quality, and architecture compromises.

🔒

Proprietary Relays & Paywalls

Most commercial cross-platform display apps route video frames through remote cloud servers or require ongoing subscriptions.

📡

High Latency & Frame Stutter

Protocols built on WebRTC or TCP struggle with jitter control and frame pacing on high-refresh-rate displays (120Hz/144Hz).

🖥️

No macOS → Windows Path

Existing open-source tools like Sunshine/Moonlight are optimized for Windows hosts. No lightweight daemon exists for macOS hosts streaming to Windows viewers.

✅
Renderd's solution: Pairs Apple's zero-copy ScreenCaptureKit and VideoToolbox hardware encoder directly with Windows' low-overhead Direct3D12 / MediaFoundation decoder over a custom QUIC transport layer — delivering display-class latency without any cloud dependency.

Capabilities

Built for Performance

⚡

Zero-Copy Pipeline

Direct IOSurface binding to VideoToolbox on macOS. Direct3D12 swapchain presenting on Windows. No unnecessary CPU copies anywhere in the critical path.

🔄

Adaptive Bitrate (ABR)

Real-time congestion control adjusting encoder bitrate dynamically based on fragment loss rate and arrival jitter. Dual-timescale: 100ms reactive + 500ms proactive.

🕐

Vsync Phase Sync

Monotonic clock alignment adjusting host frame dispatch to match viewer vertical display refresh intervals. Eliminates the dual-vsync penalty that plagues other solutions.

🔐

SPAKE2+ Pairing

One-time secure pairing via 6-digit PIN using SPAKE2+ (RFC 9382). Subsequent sessions use mutual TLS within QUIC. PairToken stored in system keychain.

📐

Layered Configuration

Flexible settings via defaults, renderd.toml, RENDERD_* environment variables, or CLI flags. Powered by Figment for ergonomic multi-source config.

🔍

Auto LAN Discovery

Zero-configuration discovery using mDNS/Bonjour (_renderd._udp.local.). Manual IP fallback for enterprise environments with restricted multicast.

System Design

Control Plane + Data Plane

Renderd separates control plane signaling (QUIC Stream 0 with Protobuf framing) from data plane frame delivery (QUIC Datagrams with 16-byte fixed headers).
